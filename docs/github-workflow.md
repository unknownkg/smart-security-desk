# GitHub workflow и подготовка выпуска

Работа ведётся в [репозитории Smart Security Desk](https://github.com/unknownkg/smart-security-desk) без переписывания опубликованной истории. До публикации рабочего кода и документации следует проверять состояние `main`, состав изменений и результаты тестов. Рабочую базу и незакоммиченные данные не следует включать в PR автоматически.

## Учебный сценарий дефекта

В основной ветке проверка статуса инцидента уже существовала. Для упражнения от неё создана ветка `exercise/incident-validation`, где проверку временно отключили отдельным коммитом. На изолированной базе запрос со статусом `closed` вернул HTTP 200, а статус сохранился: [результат до исправления](evidence/branch-exercise-before.json).

Проблема зарегистрирована в [Issue #12](https://github.com/unknownkg/smart-security-desk/issues/12). В ветке `fix/incident-validation` проверку восстановили и повторили сценарий: HTTP 400, статус сохранён как `new` — [результат после исправления](evidence/branch-exercise-after.json). [PR #13](https://github.com/unknownkg/smart-security-desk/pull/13) проверен и слит в `exercise/incident-validation`; после этого Issue закрыт вручную. Намеренный дефект не переносился в `main`.

Отдельно сохранены прежние результаты в изолированной копии: [ответ до восстановления](evidence/incident-invalid-status-before.json), [ответ после восстановления](evidence/incident-invalid-status-after.json), [TC-06 до исправления](evidence/tc06-exercise-before.txt) и [TC-06 после исправления](evidence/tc06-exercise-after.txt). Они не выдаются за результаты проверок учебной ветки.

## Подготовка выпуска

Основу и API камер, событий и инцидентов объединили в `main` через [PR #9](https://github.com/unknownkg/smart-security-desk/pull/9), [PR #10](https://github.com/unknownkg/smart-security-desk/pull/10) и [PR #11](https://github.com/unknownkg/smart-security-desk/pull/11). Статус последующих PR, текущий коммит `main` и выпуск следует сверять с GitHub: локальное состояние само по себе не подтверждает публикацию.

Перед выпуском нужны проверка актуальной опубликованной версии, автоматических тестов и всех маршрутов, просмотр интерфейса на разных размерах экрана и проверка отсутствия секретов. Коллекцию можно импортировать в Postman Desktop или Postman Web с Desktop Agent и выполнить по инструкции в [README](../README.md). При отсутствии доступа к Postman сохранённый [отчёт Newman](evidence/newman-report.json) подтверждает только отдельный запуск из командной строки.

Тег и GitHub Release `v1.0.0` создаются после обязательного workflow и технической приёмки. Если обязательная ручная проверка приёмки остаётся невыполненной, выпуск нельзя считать подтверждённым. Видео для CAM-01 не входит в обязательный MVP и может быть подключено позже.
