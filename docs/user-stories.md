# User Stories и Acceptance Criteria

## US-01. Просмотр камер

Как оператор, я хочу видеть камеры, чтобы оценить их состояние и открыть доступный preview.

Критерии приёмки: для каждой камеры доступны id, name, location, status и previewUrl; состояние отображается как online или offline.

## US-02. Просмотр событий IoT

Как оператор, я хочу видеть события IoT, чтобы замечать изменения на объекте.

Критерии приёмки: событие содержит тип, идентификатор камеры, уровень важности и время (type, cameraId, severity, createdAt).

## US-03. Создание инцидента

Как оператор, я хочу создать инцидент, чтобы зафиксировать ситуацию для дальнейшей обработки.

Критерии приёмки: при создании передаются название, камера и уровень важности; статус автоматически устанавливается в new.

## US-04. Изменение статуса инцидента

Как оператор, я хочу менять статус инцидента, чтобы отражать ход его обработки.

Критерии приёмки: доступны статусы new, in_progress, resolved; недопустимый статус отклоняется.

## US-05. Изменение состояния камеры

Как инженер, я хочу менять состояние камеры, чтобы информация соответствовала её доступности.

Критерии приёмки: допустимы состояния online и offline; после изменения обновляется updatedAt.

## US-06. Фильтрация инцидентов

Как пользователь, я хочу фильтровать инциденты, чтобы быстро находить нужные записи.

Критерии приёмки: список можно фильтровать по status и severity.
