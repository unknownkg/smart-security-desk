# Smart Security Desk

Smart Security Desk — учебное веб-приложение для централизованного просмотра состояния камер видеонаблюдения, регистрации событий IoT и обработки инцидентов безопасности. Оператор работает с данными через панель Operations Console, а сервер хранит их в JSON-файле.

## Назначение проекта

Когда сведения о камерах, сигналах датчиков и инцидентах находятся в разных местах, оператору сложнее увидеть общую ситуацию и проследить за обработкой проблем. Smart Security Desk собирает эти сведения на одной панели: здесь можно проверить камеры, просмотреть события и заняться очередью инцидентов. Проект представляет собой учебный MVP; его применение в действующей службе безопасности не заявляется.

## Возможности приложения

- Просмотр списка камер и переключение их состояния между `online` и `offline`.
- Просмотр подключённого видео; отдельные сообщения для отсутствующего источника, недоступной камеры и ошибки загрузки потока.
- Просмотр журнала событий IoT с фильтрами по камере и важности.
- Регистрация инцидентов, изменение их статуса и назначение ответственного.
- Фильтрация инцидентов по статусу и важности.
- Панель показателей по текущим данным и уведомления об успешных действиях или ошибках.
- Отдельная [страница учебного задания с багом](public/bug.html) с описанием сценария проверки валидации.

## Архитектура

Браузер загружает статические файлы интерфейса и обращается через JavaScript `fetch` к REST API Express. Сервер читает `data/db.json` и записывает изменения в тот же файл. Авторизация, отдельная СУБД и видеосервер в состав приложения не входят.

```text
Браузер → JavaScript fetch → Express REST API → data/db.json
```

Основные файлы и каталоги:

```text
server.js                          запуск сервера и подключение маршрутов
routes/                            маршруты камер, событий и инцидентов
data/db.json                       данные приложения
public/index.html                  панель оператора
public/bug.html                    учебное задание с багом
public/style.css                   оформление страниц
public/app.js, public/toast.js     логика интерфейса и уведомлений
public/evidence/                   материалы для страницы задания
tests/                             автоматические проверки
postman/                           коллекция API
docs/                              требования, описание дефекта и доказательства
```

## Установка и запуск

Установите актуальную LTS-версию Node.js с npm. В каталоге проекта выполните:

```sh
npm install
npm start
```

Панель доступна по адресу [http://localhost:3000](http://localhost:3000), проверка сервиса — [http://localhost:3000/api/health](http://localhost:3000/api/health). По умолчанию используется порт `3000`; его можно изменить переменной окружения `PORT`. По умолчанию данные читаются из `data/db.json`; для изолированной проверки можно указать путь к отдельному JSON-файлу через `DB_PATH`.

## REST API

Тела запросов и ответы передаются в JSON. Ошибки API имеют вид `{"error":"..."}`.

| Метод | Путь | Назначение |
| --- | --- | --- |
| `GET` | `/api/health` | Проверить доступность сервиса |
| `GET` | `/api/cameras` | Получить список камер |
| `PATCH` | `/api/cameras/:id` | Изменить `status` камеры на `online` или `offline` |
| `GET` | `/api/events` | Получить события; необязательные фильтры `severity`, `cameraId` |
| `POST` | `/api/events` | Создать событие с полями `type`, `cameraId`, `severity`, `message` |
| `GET` | `/api/incidents` | Получить инциденты; необязательные фильтры `status`, `severity` |
| `POST` | `/api/incidents` | Создать инцидент с полями `title`, `cameraId`, `severity` и необязательным `description` |
| `PATCH` | `/api/incidents/:id` | Изменить `status` и/или `assignee` инцидента |

Создание возвращает HTTP `201`, успешное чтение или изменение — `200`, неверные данные — `400`, неизвестный идентификатор камеры или инцидента — `404`. Допустимые статусы инцидента: `new`, `in_progress`, `resolved`; новый инцидент всегда получает статус `new`. События и инциденты выдаются в порядке убывания времени создания.

## Тестирование

Автоматические проверки запускаются командой:

```sh
npm test
```

Тесты проверяют API с временной базой, состояния предпросмотра, интерфейсную логику, уведомления и регрессию недопустимого статуса. Для ручного запуска в Postman Desktop или Postman Web с Desktop Agent импортируйте [коллекцию](postman/Smart-Security-Desk.postman_collection.json), запустите сервер и выполните коллекцию по порядку через Collection Runner. Переменная `baseUrl` по умолчанию равна `http://localhost:3000`; TC-04 сохраняет идентификатор для TC-05 и TC-06. Коллекция создаёт записи, поэтому используйте отдельную копию базы через `DB_PATH`.

Коллекция охватывает обязательные сценарии:

| Сценарий | Проверка |
| --- | --- |
| TC-01 | Доступность сервиса |
| TC-02 | Создание корректного события |
| TC-03 | Отклонение события без `cameraId` |
| TC-04 | Создание инцидента |
| TC-05 | Изменение статуса на `in_progress` |
| TC-06 | Отклонение недопустимого статуса `closed` |
| TC-07 | Обращение к неизвестной камере |
| TC-08 | Фильтрация инцидентов по статусу `new` |

Сохранённый [результат Newman](docs/evidence/newman-report.json) относится к отдельному запуску коллекции: 9 запросов и 20 проверок без ошибок. Отчёт сокращён: из него исключены заголовки запросов и тела ответов. Newman запускает коллекцию из командной строки; этот результат не является подтверждением запуска в Postman Desktop или Postman Web с Desktop Agent. Для такой проверки импортируйте коллекцию и выполните её через Collection Runner, как описано выше. Результаты `npm test` следует проверять на текущей версии проекта перед приёмкой.

## Задание с багом

Учебный сценарий показывает, почему сервер должен проверять статус инцидента. В отдельной ветке `exercise/incident-validation` проверку временно отключили: запрос `PATCH` со статусом `closed` ошибочно получил HTTP `200`, а недопустимый статус сохранился. После восстановления проверки в ветке `fix/incident-validation` такой запрос получил HTTP `400`, статус остался `new`. Результаты этого запуска сохранены: [до исправления](docs/evidence/branch-exercise-before.json) и [после исправления](docs/evidence/branch-exercise-after.json). Ранее аналогичный сценарий проверили в изолированной копии: [ответ до восстановления](docs/evidence/incident-invalid-status-before.json), [ответ после восстановления](docs/evidence/incident-invalid-status-after.json), [TC-06 до исправления](docs/evidence/tc06-exercise-before.txt) и [TC-06 после исправления](docs/evidence/tc06-exercise-after.txt).

После запуска приложения откройте [http://localhost:3000/bug.html](http://localhost:3000/bug.html). Страница описывает упражнение и показывает его доказательства. Проблема зарегистрирована в [Issue #12](https://github.com/unknownkg/smart-security-desk/issues/12), исправление проверено и объединено в учебную ветку через [PR #13](https://github.com/unknownkg/smart-security-desk/pull/13); Issue закрыт. Проверка статуса уже присутствовала в опубликованном `main`, а намеренно созданный дефект в него не переносился.

## Ограничения

Это учебный MVP: JSON-файл не рассчитан на промышленную многопользовательскую нагрузку, промышленная аутентификация отсутствует, полноценный видеорегистратор и архив NVR не реализованы. `previewUrl` указывает на источник видео, но приложение не поставляет видеосервер и не преобразует потоки.

Для CAM-01 «Главный вход» добавлена собственная демонстрационная видеозапись `public/media/entrance.mp4` (MP4/H.264, 480×854, около 22 секунд). В исходных данных камеры указан `previewUrl: "/media/entrance.mp4"`. Запись воспроизводится в операторской панели и явно обозначается как «Демонстрационная запись», а не прямой эфир. На GitHub Pages используется отдельная статическая версия с браузерными демоданными; видео подключено и в ней. Встроенное воспроизведение HLS зависит от поддержки браузера; страница WebRTC открывается отдельной ссылкой. Состояние камеры и доступность её видеопотока отображаются отдельно.

По сравнению с примером методички маршруты вынесены в `routes/`, а проверка входных данных строже: PATCH принимает предусмотренные поля, пустые обязательные строки и недопустимые статусы отклоняются. Добавлена обработка некорректного JSON и ошибок сервера; восемь обязательных маршрутов сохранены.
